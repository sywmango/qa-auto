## 3. 데이터 규칙 (사용자 지시)
- 만든 데이터는 **삭제하지 않음**. 예방작업(주기) 자체는 절대 삭제 금지.
- 대표 이름 칸(작업명, 점검항목, 제목 등) 맨 앞에 `[sychoi]`, 실행마다 겹치지 않는 현실적인 이름 (`uniqueName()` = 설비 + 점검 종류 조합).
- 사원 칸(담당자·작성자 등)은 로그인 사용자 **최신영** (사이드바 `이름 [부서]` 에서 읽음).
- 생성 테스트는 상세의 **모든 수정 가능한 칸**을 채우고, 저장 후 다시 열어 상세·목록과 칸별 비교.
- 설비는 반드시 Lov(돋보기) 팝업에서 선택.
- 하위 항목은 테스트가 추가한 것만 삭제 가능. 삭제 후 같은 종류를 다시 추가해 **하위 목록이 비지 않게** (8001·8004 모두 설비·표준작업·점검항목·첨부문서 각 1건 이상).
- EC_016(일정 있는 주기 삭제): 삭제 버튼 → 확인창이 뜨면 Cancel, 미수행으로 기록.
- 기존 데이터(테스트가 만들지 않은 것)는 어떤 것도 삭제 금지.

## 6. 알려진 함정
- 결과 엑셀이 엑셀에서 열려 있으면 저장 시 PermissionError → 새 이름으로 저장.
- 번호마다 메뉴를 다시 여는 방식(예: 7990~8010 개별 조회)은 테스트 제한시간 초과 → 한 번 검색 후 목록에서 추릴 것.
- 상세 화면은 networkidle 이 오지 않을 때가 있음 → `settle()` 은 최대 8초만 대기.
- 상세보기·Linked·Excel 은 팝업이 아니라 **새 브라우저 창**으로 열림 (Excel 은 새 창에서 다운로드).
- Lov 팝업 닫기 버튼은 팝업 iframe(`popupIframe1`) 안의 `div.b_pwin_close`.
- 저장 확인창은 `OK/Cancel`, 안내 메시지는 `확인` 버튼.
- `test-results/` 는 실행마다 지워짐 → 보관할 데이터는 `playwright/.data/`.
- `npx tsc` 는 이 프로젝트에 없음(엉뚱한 패키지가 실행됨). 타입 확인은 playwright 실행으로.
