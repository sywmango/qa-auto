마지막 정리: 2026-10-20. 최종 결과는 `docs/AD230_UT_정기점검주기_v15.xlsx`, `docs/report/AD230_정기점검주기_테스트결과보고서_v15.pdf`
(정상 47, 오류 4, 개선 7). 이전 버전은 `docs/이전버전/`.

## 1. 한 번에 돌리기

D:\qa-auto 에서 PowerShell:

```
.\run-ad230.ps1          # 전체: 새 [sychoi] 주기로 처음부터 → 엑셀·PDF 까지 (약 3시간)
.\run-ad230.ps1 view     # 조회만 (데이터 안 바뀜, 약 6분)
.\run-ad230.ps1 report   # 이미 돌린 결과로 엑셀·PDF 만 다시
```

- 단계: `view` 조회 → `data` 생성·수정·하위목록·일정 → `extra` 주기구분·표시형식 → `complete` 작업완료 후 재조정 → `delete` 삭제 → `evidence` 오류 캡처 → `report` 엑셀·PDF
- 결과: `docs\AD230_UT_정기점검주기_<날짜>.xlsx`, `docs\report\AD230_정기점검주기_테스트결과보고서_<날짜>.pdf`
- AD230 테스트는 주기를 만들고·완료하고·삭제하므로 평소 `.\run-tests.ps1` 에서는 빠지고, `run-ad230.ps1` 로만 돈다 (`RUN_AD230=1`).
- 돌린 뒤에는 결과를 한 번 보고, 테스트가 판정할 수 없는 항목은 `docs\report\판정기준.json` 에 적힌 대로 개선 등으로 바뀌어 들어간다. 새로 확인된 사양이 있으면 이 파일에 추가.

## 3. 테스트 데이터 규칙

- 만든 주기 작업명은 `[sychoi] High Speed Mixer(세종파마텍) <점검 종류>` (종류 12가지, `tests/support/pmi.ts` 의 `PM_KINDS`). 담당자는 로그인 사용자(최신영).
- 작업명은 **100바이트(한글 1자=3바이트)를 넘으면 안내 없이 저장되지 않는다** → 꼬리표는 짧게.
- 삭제는 테스트가 만든 것만. 정리: `tests/ad230/tools/cleanup.spec.ts` (발행 전 계획을 정기점검계획에서 먼저 지운 뒤 주기 삭제, 작업이 발행·완료된 주기는 남김).
- 남아 있는 예전 주기: 8007, 8017, 8018, 8041~8045, 8060, 8061 (작업 발행·완료 계획이 있어 삭제 불가).

## 4. 확인된 사양 (오류 아님)

- 설비로 검색하면 그 설비가 묶인 주기의 설비가 각각 한 행씩 나온다.
- TBM 휴일 회차는 앞 근무일로 당기고, 그날 이미 일정이 있으면 그 회차는 삭제한다 (2일 주기에서 일요일 회차 없음).
- 월 주기에서 그 달에 날짜가 없으면 말일, 한 번 말일로 맞춰지면 이후 말일 기준.
- 일정이 생성된 주기는 삭제할 수 없다. 계획을 먼저 지우면 삭제된다.
- RBM/UBM 첫 계획은 시작일 다음날부터 누적이 사용량을 "초과"하는 날 (40·하루 8 → 6번째 근무일).
- 지난 날짜로는 계획이 안 생기고, 앞날짜로 작업 완료는 안 된다 ("작업은 미리 완료처리할 수 없습니다").

## 6. 화면 동작 (자동화할 때 주의)

- 값은 키 입력이 있어야 "수정됨"으로 인식된다. `fill` 만 하면 [저장]이 안내 없이 아무것도 안 함 → `put()` 사용.
- 저장·일정생성 성공 안내가 없다 → 다시 열어 값으로 확인.
- 마지막 칸에서 Tab 하면 버튼 줄이 위쪽 머리줄로 옮겨진다 (`saveForm` 이 처리).
- 필수 칸은 `label.check`. 상세보기·Linked·Excel 은 새 창. Lov 가 두 개 뜨면 위의 것(`lovContentFrame`).
- 점검일정 새 창은 기간이 "지난달 1일~오늘" → `readPlans` 가 1년 뒤까지 넓힘.
- 목록 삭제는 행을 한 번 누른 뒤 체크 (체크만 하면 동작 안 할 때가 있음).
- QA 서버가 가끔 `/dream/index.do` 404 (재배포) → 30초마다 확인 후 이어서.
