# Claude와 테스트 자동화 협업 가이드

마지막 정리: 2026-10-22 (AD230 정기점검주기, AD210 정기점검계획, AP591 정기점검실행 3개 메뉴와 공통 테스트 정리 기준)

## 1. 한눈에 보기

| 누가 | 하는 일 |
| --- | --- |
| **사용자** | 메뉴 테스트 요청, 업무 규칙·로직 문서 전달, 결과 중 "사양인지 오류인지" 확인, PR 확인 후 "머지해줘" |
| **Claude** | 화면 탐색, 테스트 케이스 작성, 자동 테스트 코드 작성·실행, 결과 판정, 엑셀·PDF 작성, 진행 상황 보고, PR 생성·머지 |

## 2. 진행 순서 (메뉴 하나 기준)

1. **요청**: 프로젝트 채팅에 "○○ 메뉴 테스트해줘"라고 쓴다. 메뉴마다 새 스레드 하나로 진행한다 (스레드가 길어지면 느려짐). 스레드는 회사 PC(CSY, D:\qa-auto)에서 원격으로 실행된다.
2. **자료 전달** (있으면): 그 메뉴의 업무 규칙, 로직 문서, 실제 사용 순서, 특별한 기능 설명. 말로 적어도 되고 파일을 올려도 된다.
3. **Claude 작업**: 화면을 직접 열어 보고 → 화면 정의 파일 추가 → 공통 테스트 먼저 실행 → 메뉴 고유 기능 테스트 작성·실행 → 결과 판정 → 회사 양식 엑셀·PDF 작성.
4. **검토**: Claude가 오류·개선으로 본 항목을 사용자에게 설명한다. 사용자가 "이건 원래 그렇게 동작해(사양)" 또는 "오류 맞아"를 알려 준다.
5. **마무리**: 판정을 고친 최종 엑셀·PDF를 받고, 코드는 PR로 올라오면 사용자가 확인 후 "머지해줘"라고 하면 Claude가 머지한다.

## 3. 테스트 코드 구조 (공통 / 메뉴별)

모든 메뉴에 똑같이 있는 부분은 **공통 테스트 하나**로 관리하고, 메뉴마다 다른 업무 기능만 메뉴별로 만든다.

| 구분 | 무엇을 | 위치 |
| --- | --- | --- |
| **공통 부품** | 메뉴 열기, 그리드, LOV, 모든 칸 채우기·저장, Setting, 상단 공통 기능, 업무그룹설정 | `tests/support/` |
| **화면 정의** | 메뉴마다 한 파일. 메뉴 경로, 화면 여는 방법, Setting 대상만 적는다 | `tests/screens/<메뉴>.ts` |
| **공통 테스트 – Setting** | 검색·목록·상세 Field 설정, Tab 설정, 숨김·정렬값·리스트 길이·[초기화]. 화면 정의를 읽어 메뉴마다 케이스를 만든다 (케이스 번호는 메뉴 것 그대로) | `tests/common/setting.spec.ts` |
| **공통 테스트 – 상단 공통 기능** | 즐겨찾기, 업무그룹(업무그룹설정과 함께), Tab설정, 편집모드(위쪽 탭·검색 필드·상세 필드 옮기기). 모든 메뉴가 같은 코드라 **대표 메뉴(정기점검주기) 한 곳에서만** 깊게 확인 | `tests/common/header.spec.ts` |
| **전체 메뉴 점검** | 192개 메뉴가 열리는지 + 상단 아이콘이 있는지 (Tab설정은 위쪽 탭이 있는 화면만) | `tests/menu-all.spec.ts` |
| **메뉴별 테스트** | 조회, 생성·수정·삭제, 메뉴 고유 기능(예: 일정확정, 재조정) | `tests/<메뉴>/` |

새 메뉴는 **화면 정의 파일 하나만 추가하면** 공통 테스트가 자동으로 그 메뉴에도 돈다.

## 4. 사용자가 준비해 주면 좋은 것

- **업무 규칙 / 기대 결과**: 예) "RBM은 시작일 다음날부터 누적하고, 누적이 주기값을 초과하는 날 계획 생성"
- **사양 확인**: Claude가 오류라고 본 것 중 원래 의도된 동작인지 알려 주기
- 녹화(codegen)는 필수가 아니다. 화면은 Claude가 직접 탐색한다.
- "하지 말 것" 목록이나 알려진 버그 목록은 따로 안 줘도 된다. Claude가 판단해서 결과에 적는다.

## 5. Claude가 하는 것

- **화면 탐색**: 회사 PC(D:\qa-auto)에서 원격으로 실행. 검색·목록·상세·하위목록·팝업(LOV)·새 창까지 확인.
- **테스트 케이스 작성**: 공통 케이스(조회·생성·수정·삭제·Excel·Setting 등) + 메뉴 고유 기능. 케이스마다 "조건 → 결과 → (오류면) 기대"로 짧게.
- **테스트 데이터**: 이름 앞에 `[sychoi]`, 모든 칸을 현실적인 값으로 채움, 사원 칸은 최신영. 다른 사람·원본 데이터는 절대 지우지 않음. 테스트로 바꾼 설정(Setting, 즐겨찾기, 업무그룹, 탭·필드 순서)은 끝나면 원래대로 되돌림.
- **판정**: 업무 규칙과 달력 데이터로 **정확한 기대 날짜·값**을 계산해 비교. 오류는 날짜 표 등으로 쉽게 설명.
- **진행 보고**: 짧게, 실제로 확인된 것만. 시각은 한국시간(KST).

| 명령 | 하는 일 | 시간(대략) |

## 8. 한계와 주의

- **Claude(클라우드)는 QA 서버에 직접 못 들어간다** (회사 IP만 허용). 그래서 모든 실행은 회사 PC에서 한다.
- **회사 PC가 켜져 있고 Claude 데스크톱 앱이 실행 중이어야** 한다. PC가 꺼지면 작업이 멈췄다가 켜지면 이어진다.
- **같은 계정으로 두 테스트를 동시에 돌리면 서로 로그아웃된다.** 메뉴 테스트는 하나씩 차례로.
- **오래 걸린다**: 데이터 생성·작업완료·삭제까지 하는 전체 실행은 몇 시간.
- 테스트 중에 결과 **엑셀 파일을 PC에서 열어 두면 저장이 막힌다**. 볼 때는 복사본으로.
- QA 서버 재배포 중(404)에는 기다렸다가 이어서 한다.
- 개선 항목은 회사 일정상 바로 안 고쳐질 수 있어 다음 차수에도 개선으로 남긴다.
