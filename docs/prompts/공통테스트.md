## 1. 목적

| 묶음 | 확인하는 것 | 코드 |

| 상단 공통 기능 | 즐겨찾기, 업무그룹(업무그룹설정과 함께), Tab설정, 편집모드(위쪽 탭·검색 필드·상세 필드 옮기기) | `tests/common/header.spec.ts` |

## 2. 입력 자료

- 메뉴별 화면 정의: `tests/screens/<메뉴>.ts` (규격은 `tests/screens/types.ts`)
- 공통 부품: `tests/support/setting.ts`, `header.ts`, `workgroup.ts`, `dream.ts`, `form.ts`
- 공통 UT 양식: `docs/UT_공통테스트케이스_AD230기준.xlsx`
- 지난 공통 오류: `docs/common/상단공통_오류목록.md`

## 3. 범위

**한다**
- Setting: 화면 정의(`fields` / `lists` / `tabs`)에 적힌 대상마다
  - 숨기기 → 화면에서 사라지는지 → 보이기
  - 정렬값 바꿔 `anchor` 뒤로 옮기기 → 화면 순서 확인
  - 목록: 칼럼 너비, 리스트 길이(-/+, 숫자)
  - [초기화] → **다시 로그인하지 않고** 바로 원래대로 돌아오는지
  - Edit 모드에서 바꿀 수 있는 칸 확인
  - 설정의 Display 여부와 화면 라벨 비교 (`compare: true`)
- 상단 공통 기능: 대표 메뉴 **정기점검주기(AD230) 한 곳에서만** 깊게 (`header.deep: true`). 모든 화면이 같은 코드이기 때문.
- 전체 메뉴 점검: 아이콘 규칙
  - 즐겨찾기·업무그룹·편집모드 아이콘: 모든 화면
  - Tab설정 아이콘: 위쪽 탭이 있는 화면만

**하지 않는다**
- 메뉴 고유 기능(조회 조건, 생성·수정·삭제, 일정확정 등) → 메뉴별 프롬프트에서
- 상단 공통 기능을 메뉴마다 깊게 반복하기

## 4. 테스트 데이터

- Setting·즐겨찾기·업무그룹·탭/필드 순서는 **사용자별 저장**이다. 바꾼 것은 테스트 끝에 반드시 원래대로 되돌린다.
- Tab 설정 원복은 [초기화]가 안 되면 Edit 로 Display Y 저장해서 되돌린다.
- 업무그룹은 `[sychoi] 자동테스트` 를 만들어 쓰고 끝에 지운다. 다른 업무그룹은 건드리지 않는다.
- 원복 도중 세션이 끊기면(같은 계정 다른 로그인) 다시 로그인한 뒤 Setting 화면에서 원래 값인지 확인한다.

## 5. 판정 규칙

**정상 (사양, 사용자 확인됨)**
- Setting Edit 로 바꿀 수 있는 칸은 정렬값·Display (목록은 너비도). 화면표시명·정렬 Left/Right·조회순서·Background Color 를 못 바꾸는 것은 정상. (2026-10-21)
- Tab 설정 [초기화]는 바로 반영돼야 정상. 2026-10-21 재배포 후 정상. (2026-10-21)
- 리스트 길이는 [초기화]로 돌아오지 않는 것이 정상. (2026-10-21)
- 위쪽 탭 Tab설정 팝업의 [Edit] 칸이 모두 읽기전용인 것은 정상. 순서는 편집모드로만 바꾼다. (2026-10-22)

**오류**
- 설정에서 Display Y 인데 화면에 안 보임 (또는 반대)
- [초기화] 후 다시 로그인해야 반영됨
- 아이콘 규칙과 다름 (예: 위쪽 탭이 없는데 Tab설정 아이콘이 있음)
- 업무그룹 아이콘이 없거나, 업무그룹에 넣은 화면이 열리지 않음

**알려진 오류** (`docs/common/상단공통_오류목록.md`, 2026-10-22): 편집모드 3초 안에 끄면 순서 저장 안 됨 / Process센터·Layout센터 업무그룹 / 개인정보 Tab설정 아이콘. 다시 테스트할 때는 이 목록의 항목이 고쳐졌는지 먼저 확인한다.

## 6. 산출물

- 공통 오류 목록 갱신: `docs/common/상단공통_오류목록.md` ("조건 → 결과 → 기대" 표)
- Setting 결과는 각 메뉴 엑셀의 Setting 케이스(메뉴 케이스 번호 그대로, 예: `AD230_TC_026`)에 들어간다. 별도 엑셀은 만들지 않는다.
- 결과 JSON: `playwright\.data\common-results\<단계>.json`

## 7. 질문 기준

**묻지 말고 진행**
- 어떤 필드·칼럼으로 Setting 을 확인할지 → 화면 정의에 없으면 검색 영역의 보이는 필드 중 필수가 아닌 첫 필드, 목록은 숫자가 아닌 칼럼 하나를 골라 화면 정의에 적는다.
- 상단 공통 기능 대표 메뉴 → 정기점검주기(AD230)
- 위 5번에 있는 사양 항목의 판정

**꼭 묻기**
- 5번에 없는 새로운 동작이 오류인지 사양인지
- 알려진 오류 목록의 항목이 "고쳐졌다"고 판정을 바꿀 때 (결과를 보여 주고 확인)

## 9. 실행 방법

```
.\run-common.ps1                          # 전체: Setting(AD230 → AD210 → AP591) → 상단 공통 기능
.\run-common.ps1 header                   # 상단 공통 기능만
.\run-common.ps1 setting -Menus AD230     # Setting 을 원하는 메뉴만
npx playwright test menu-all              # 전체 메뉴 점검 (약 8분)
```

mssql 사이트(1290)에서 돌릴 때 (2026-10-26)
```
$env:QA_SITE="mssql"; .\run-common.ps1    # 결과·로그·로그인 파일은 playwright\.data\mssql 아래 따로
# 처음 한 번: [sychoi] 정기점검 데이터 만들기 (번호는 playwright\.data\mssql\site-data.json)
$env:QA_SITE="mssql"; $env:RUN_AD230='1'; npx playwright test ad230/setup/site-pm
$env:QA_SITE="mssql"; $env:RUN_AD230='1'; npx playwright test ad230/setup/site-work
```
사이트마다 메뉴 번호가 달라 메뉴는 번호의 이름이 다르면 이름으로 찾는다. 결과 비교는 `docs/common/상단공통_오류목록.md` 의 "사이트별 결과".

새 메뉴를 공통테스트에 넣으려면: `tests/screens/<메뉴>.ts` 를 만들고 `run-common.ps1` 의 `$Menus`·`$auth` 에 추가한다.

검색·목록·상세 공통 케이스 (2026-10-29)
```
$env:RUN_AD230='1'; npx playwright test common/screen     # 메뉴는 RUN_<화면ID> 로 고름. run-<메뉴>.ps1 view 단계가 같이 돌림
```
새 메뉴: 화면 정의에 `view` 를 적으면(검색 칸 DTO, 목록 기준 열, 비교할 조건, 상세 프레임·칸) 공통 케이스가 그 메뉴 테스트ID 로 생긴다. 메뉴 코드에는 그 메뉴에만 있는 규칙만 쓴다.
