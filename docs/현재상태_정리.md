## ② 회사 Git 에 올릴 폴더 (`D:\qa-export`)

회사 Git 주소를 받으면 이 폴더 안 내용을 그대로 저장소 맨 위에 넣으면 됩니다. `D:\qa-auto` 원본은 건드리지 않았습니다.

```
D:\qa-export\
├─ .claude\commands\qa.md      ← /qa 명령어 (Claude Code 가 이 위치에서만 알아봄)
└─ claude\qa\
   ├─ README.md                ← 읽는 순서, 폴더 설명, 하지 말 것
   ├─ common.md                ← 모든 프로젝트 공통 규칙
   ├─ dream41.md               ← Dream 4.1 전용 규칙
   ├─ menus\                   ← 메뉴별 md 4개 (AD210, AD230, AP591, AZ303)
   ├─ templates\               ← 새 메뉴 md 틀, 회사 UT 양식 5개
   ├─ results\<화면ID>\         ← UT 엑셀·보고서 최종본, 판정기준, 오류 캡처, 설계서
   └─ playwright\              ← 테스트 코드 (오늘 정리한 코드로 다시 복사해 둠)
```

### 각 md 에 들어 있는 것

| 파일 | 내용 |
| --- | --- |
| `qa.md` | **팀장님 명령어 6개와 진행 흐름은 문서 그대로.** 아래에 "추가 제안"만 덧붙임: `--site`(oracle/mssql/both), 케이스 지정(`/qa AD230 EC_003`), 설계서 찾는 순서, 오류 캡처 저장, PR·브랜치 QA 때 UT 만드는 법, 공통은 메뉴마다 새로 만들지 않기 |
| `common.md` | 테스트 데이터(`[본인ID]`), 실행(같은 계정 동시 실행 금지, 밤 실행은 작업 스케줄러), 판정 기준, UT 엑셀 규칙, 화면 캡처 규칙, 꼭 물어볼 것, 메뉴 md 칸 규격, **공용 파일은 덧붙이기만**, 완료 조건 |
| `dream41.md` | 사이트 2곳(oracle 1220 / mssql 1290), 화면 구조, 화면 동작(키 입력해야 저장 등), 버튼 class 표, 공통 기능(Setting·상단·전체 메뉴) 사양과 알려진 오류, **공통 동작 기준**(검색·목록·상세·생성·삭제·Excel·입력 검증), 공통 코드 부품 표, **공통은 한 번만** |
| `menus\<화면ID>.md` | 그 메뉴의 범위, 테스트 데이터, 확인된 사양, 알려진 오류, 실행 방법, 인수인계 (예전 prompt + handoff 를 합침) |

메뉴 목록 표는 3명이 동시에 고치면 충돌이 나서 빼고, `menus\` 폴더의 파일 자체를 목록으로 씁니다.

## ③ 메뉴마다 중복된 코드 정리 (팀장님 방향 "같은 걸 메뉴별로 계속 만들지 말 것")

### 전에는

AD230·AD210·AP591 세 메뉴 모두에 "검색 기본값, Lov, 조건 검색, 정렬, 건수, 상세 열기, 목록=상세, 읽기전용, 닫기, 체크 없이 삭제, Excel" 확인 코드가 **각각 따로** 있었습니다. 같은 확인을 세 번 짠 것입니다.

### 지금은

| 무엇 | 어디 |
| --- | --- |
| 공통 확인 방법 (한 번만 짬) | `tests/common/screen.spec.ts` |
| 메뉴마다 다른 것 (검색 칸 ID, 목록 열, 상세 칸) | `tests/screens/<메뉴>.ts` 의 `view` — 표처럼 적기만 함 |
| 그 메뉴에만 있는 탭 확인 (카렌다 등) | `view.extra` → `tests/support/pmplan-view.ts`(AD210), `pmexec-view.ts`(AP591) |
| 메뉴 고유 규칙 (주기 계산, 일정 확정, 결재 흐름 등) | 그대로 메뉴 코드 (`tests/ad230/` 등) |

- 메뉴 코드에서 지운 중복: **45건** (AD230 17, AD210 15, AP591 13)
- **테스트ID 와 UT 엑셀 행은 그대로**입니다. 결과 엑셀 만드는 방법도 그대로입니다.
- `run-ad230.ps1` 등 실행 파일의 `view` 단계가 공통 케이스도 같이 돌립니다. 사용법은 전과 같습니다.

### 새 메뉴를 할 때

`tests/screens/<화면ID>.ts` 에 `view` 만 적으면 공통 케이스 15~18건이 바로 생깁니다. 메뉴 코드는 그 메뉴 고유 규칙만 짜면 됩니다.

### 제대로 됐는지 확인한 방법

| 확인 | 결과 |
| --- | --- |
| oracle 에서 새 공통 코드 실행 → 예전 판정과 비교 | 같음 (AD210 의 알려진 오류 TC_016 도 그대로 잡음) |
| AD230 에서 다르게 나온 4건 | **예전 코드로 다시 돌려도 오늘 똑같이 실패** → 정리 탓이 아니라 오늘 QA 서버 상태 |
| mssql 에서 3개 메뉴 실행 | 실행됨. 사이트 차이는 아래 "확인 필요" |
| 메뉴에 남긴 케이스 (AD230 TC_008·026, AD210 TC_017·EC_012) | 다시 돌려 통과 |
