# QA 자동화 사용법 (2026-10-29)

지금 쓰는 방법(① ②)과, 회사 Git 으로 옮긴 뒤 쓸 방법(③)으로 나눴습니다.
모든 실행은 **회사 PC `D:\qa-auto`, PowerShell** 에서 합니다 (QA 서버는 회사 IP 만 접속).

---

## 0. 꼭 지킬 것

- **같은 계정으로 두 테스트를 동시에 돌리지 않는다.** 새로 로그인하면 먼저 돌던 쪽 세션이 끊깁니다. 다른 사이트(oracle·mssql)끼리도 마찬가지, oracle → mssql 순서로 하나씩.
- 테스트가 만든 데이터에는 `[내 로그인 ID]` 가 붙고 (`.env` 의 `QA_USER_ID`, 따로 설정 없음), 지우는 것도 내 태그 데이터만 지웁니다.
- 주기 8007 같은 **팀 공용 기준 데이터**는 같이 쓰고 지우지 않습니다 (목록: `dream41.md` 1장).
- Setting·즐겨찾기·업무그룹은 바꿨다가 테스트 끝에 원래대로 돌려 놓습니다.
- 밤새 돌릴 때는 Claude 에게 맡기지 말고 Windows 작업 스케줄러로 `.ps1` 을 돌립니다.

## ① Claude 에게 맡기기 (지금 가장 많이 쓰는 방법)

Claude Code 앱에서 `D:\qa-auto` 폴더로 대화를 열고 말로 부탁합니다. Claude 는 `CLAUDE.md` 를 먼저 읽고 기본값대로 진행합니다.

| 하고 싶은 것 | 이렇게 말하기 (예) |
| --- | --- |
| 메뉴 하나 단위테스트 | "정기점검주기(AD230) 단위테스트 해줘" |
| 오류 하나만 다시 확인 | "AD230 EC_003 다시 확인해줘" |
| 결과 엑셀·보고서만 다시 | "AD230 보고서 다시 만들어줘" |
| 새 메뉴 시작 | "결재요청(AZ303) 테스트 시작해줘. 설계서는 D:\...\설계서.pptx" |

Claude 가 묻는 것은 이것뿐입니다: 처음 보는 동작이 오류인지 사양인지(마지막에 한 번에), 판정을 바꿀 때, 내 태그가 아닌 데이터를 건드려야 할 때, 머지. 답하면 메뉴 md 에 날짜와 함께 적혀 다시 묻지 않습니다.

## ② 직접 실행하기 (PowerShell)

### 메뉴 단위테스트

```
.\run-ad230.ps1                 # 정기점검주기 전체 (약 3시간, 주기를 새로 만들고 완료·삭제)
.\run-ad230.ps1 view            # 조회만 (데이터 안 바뀜, 약 12분) ← 공통 케이스 + 메뉴 케이스
.\run-ad230.ps1 report          # 이미 돌린 결과로 엑셀·PDF 만 다시
.\run-ad210.ps1 view            # 정기점검계획 조회만
.\run-ap591.ps1 view            # 정기점검실행 조회만
.\run-az303.ps1                 # 결재요청 (되돌릴 수 없는 결재완료가 남음)
```

mssql 사이트에서 돌릴 때는 앞에 사이트를 지정하고, 끝나면 지웁니다.

```
$env:QA_SITE="mssql"; .\run-ad230.ps1 view
Remove-Item Env:QA_SITE
```

### 메뉴 공통 기능

```
.\run-common.ps1                # Setting(3개 메뉴) → 상단 공통 기능
.\run-common.ps1 setting -Menus AD230
npx playwright test menu-all    # 전체 메뉴 192개 열림·아이콘 (약 8분)
```

### 결과는 어디에

| 무엇 | 위치 |
| --- | --- |
| UT 엑셀 | `docs\<화면ID>\<화면ID>_UT_<메뉴>_v<n>.xlsx` |
| 결과보고서 PDF | `docs\<화면ID>\report\` |
| 오류 캡처 | `docs\<화면ID>\report\evidence\` |
| 실행 로그 | `playwright\.data\logs-<메뉴>\` (mssql 은 `playwright\.data\mssql\...`) |
| 실패 화면·영상 | `test-results\` (다음 실행 때 지워짐) |

## ③ 오늘 정리한 코드 구조

### 한눈에

```
tests\
├─ common\screen.spec.ts     ← 검색·목록·상세 공통 확인 (모든 메뉴가 같이 씀) ★ 오늘 새로
├─ common\setting.spec.ts    ← Setting 공통
├─ common\header.spec.ts     ← 즐겨찾기·업무그룹·편집모드 공통
├─ screens\<메뉴>.ts          ← 메뉴마다 "어느 칸, 어느 열" 만 적는 화면 정의
├─ support\                  ← 부품 (메뉴 열기, 버튼, 값 넣기, 저장 등)
└─ ad230\, ad210\, ap591\, az303\  ← 그 메뉴에만 있는 규칙 (주기 계산, 일정 확정, 결재 흐름 등)
```

### 공통 케이스가 하는 확인 (메뉴마다 같은 테스트ID 로 생김)

검색 기본값 / 설비 Lov = 설비 메뉴 건수 / 그 외 Lov 열림 / 조건 하나 검색 / 조건 조합 검색 / 전체 검색 / 결과 없는 검색 / 정렬 / 건수(Total) / 행 클릭 상세 / 상세보기 새 창 / 목록=상세 값 / 목록 표시 형식 / 읽기전용 / 상세 닫기 / 체크 없이 삭제 / Excel

### 새 메뉴를 넣을 때 (Claude 에게 맡기면 Claude 가 함)

1. `tests\screens\<화면ID>.ts` 에 `view` 를 적는다. 예 (정기점검주기):
   ```ts
   view: {
     ids: { defaults: 'AD230_TC_001', searchOne: 'AD230_TC_004', ... },   // 공통 케이스 → 이 메뉴 테스트ID
     dto: 'maPmMstrCommonDTO',                                            // 검색 칸 앞부분
     key: '예방작업번호',                                                  // 목록 기준 열
     conds: [{ id: 'pmNo', col: '예방작업번호', value: (r) => r['예방작업번호'] }, ...],  // 검색해 볼 조건
     detail: { frame: '...', pairs: [['작업명', 'description'], ...], readonly: ['pmNo'] },  // 상세
   }
   ```
2. `$env:RUN_<화면ID>='1'; npx playwright test common/screen` → 공통 케이스 15~18건이 바로 돈다.
3. 그 메뉴에만 있는 규칙만 `tests\<화면ID 소문자>\` 에 짠다.

## ④ 회사 Git 으로 옮긴 뒤 (예정)

`D:\qa-export` 에 올릴 내용이 준비돼 있습니다. 올리고 나면 Claude Code 앱 입력창에서 `/qa` 로 시작합니다.

| 명령 | 뜻 |
| --- | --- |
| `/qa ADM10` | 메뉴 단위 QA (팀장님 1번) |
| `/qa ADM10 --fd "D:\svn\...\설계서.pptx"` | 설계서와 대조 (2번) |
| `/qa 236` | PR 변경 화면 (3번) |
| `/qa jaegeon_1966` | 브랜치 변경 화면 (4번) |
| `/qa ADM10 --quick` | 조회만 (5번) |
| `/qa ADM10 --report "폴더"` | 보고서 md 저장 (6번) |
| `/qa ADM10 --site mssql` | 사이트 지정 (추가 제안, 기본 둘 다) |
| `/qa ADM10 EC_003` | 케이스 하나만 (추가 제안) |

진행 순서: 명령 입력 → Claude 가 QA Plan 제시 → 검토·수정 → 확정 → QA → UT 파일.
화면은 Playwright MCP 로 Claude 가 직접 보며 확인하고, 자주 다시 볼 메뉴만 코드로 남깁니다.
