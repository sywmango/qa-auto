Playwright 외 MCP 도구 조사

2026-10-23 · Claude 웹 조사 (설치·실행은 아직 안 해 봄)

MCP = Claude가 바깥 도구(브라우저, DB, 파일 등)를 직접 쓰게 해 주는 연결 장치. 지금은 Playwright(브라우저 조작)만 쓰고 있다.

추천 순서

1Chrome DevTools MCP Google 공식 · 바로 가능

도움되는 점
화면을 열 때 콘솔 에러, 실패한 네트워크 요청, 느린 화면을 Claude가 직접 확인. 메뉴 순회 스모크(콘솔 에러 확인)와 성능 확인에 바로 쓴다.
필요한 것
설정 한 줄 (npx chrome-devtools-mcp), Chrome
주의
기본으로 사용 통계·성능 데이터를 Google 로 보냄 → 우리에게 이득이 없어 끈다. 사용 통계는 Google 이 도구를 개선하는 데만 쓰이고, 성능(CrUX)은 공개 사이트의 실제 사용자 속도를 가져오는 기능이라 회사 IP 전용 QA 서버는 데이터가 없다. 켜 두면 QA 서버 주소만 Google 로 나간다. --no-performance-crux 와 사용 통계 끄는 옵션(설치 때 README 확인)으로 끈다.

2DB 조회 MCP (읽기 전용) 효과 가장 큼 · 결정 필요

도움되는 점
① Setting 메타 테이블을 읽어 화면 정의 자동 생성
② 저장 후 DB 값 확인 (테이블.컬럼)
③ 기대 날짜 계산용 달력·계획 데이터 조회
필요한 것
DREAM DB 종류(Oracle / MSSQL 등) 확인, SELECT 권한만 있는 QA DB 계정
주의
운영 DB 금지, QA DB 만. 계정 발급은 DBA·본부장 결정 필요.

3Playwright 테스트 자동 수정 (Test Agents) 확인 불필요 · 바로 적용

한 줄로
화면이 바뀌어 깨진 테스트를 Claude가 알아서 고쳐 주는 Playwright 기본 기능
예시
재배포로 [확정] 버튼 이름이 바뀌어 30건 실패 → 이름만 고쳐 다시 통과. 진짜 오류면 고치지 않고 표시만.
필요한 것
Playwright 는 이미 설치됨. 처음 한 번 npx playwright init-agents 로 설정 파일만 만들면 됨 (1분)
적용 방법
이후 테스트가 실패하면 Claude가 이 방식으로 고치고, PR 에 "화면 변경으로 고친 부분"을 따로 표시
주의
고친 내용은 사람이 PR 에서 확인

지금은 필요 없는 것

도구이유
Excel MCPscripts/write-results.py 로 UT 엑셀 작성이 이미 됨. 추가 효과 작음
모바일 (Appium MCP, mobile-mcp)지금은 웹 QA 단계. 모바일 테스트를 시작할 때 다시 검토
GitHub MCP이 PC 의 gh 로 PR·머지 이미 됨
테스트 관리 도구 MCP (QA Sphere, TestRail 등)회사가 엑셀 UT 양식을 씀. 도입하면 다시 검토
Selenium MCP이미 Playwright 사용
BrowserStack 등 클라우드 브라우저QA 서버가 회사 IP 만 허용해 접속 불가, 유료

정해야 할 것 (본부장님 확인)

  1. Chrome DevTools MCP 를 먼저 붙여 볼지 (위험 낮음, 바로 가능)
  2. QA DB 읽기 전용 계정을 받을 수 있는지, DB 종류가 무엇인지 (가장 효과 큼)
  3. 회사 이슈 관리 도구(Jira, Redmine 등)가 있으면 오류를 바로 등록하는 MCP 도 가능
