## 1. 목적

결재요청 팝업이 설계서대로 동작하는지(결재라인 불러오기, 결재자 지정·저장, 기본결재자, 필수결재자, 승인요청)와, 결재가 되는 메뉴 27개에서 실제로 승인요청 → 결재대기 승인 → 결재완료까지 되는지 확인한다.

## 3. 범위

**한다**
- 팝업 기능 (TC_001~025, EC_001~005): 일일업무일지 [sychoi] 문서로
- 메뉴 27개 (TC_026~052): 메뉴마다 [sychoi] 문서를 만들어 승인요청 → 결재대기 승인 → 결재완료 (A안, 2026-10-26 사용자 선택)
- oracle·mssql 두 사이트 모두 (2026-10-26 사용자 지시)
- 공통테스트 적용: 아니오 (팝업 Setting 은 TC_007, TC_017 로 직접)

**하지 않는다**
- 반려·참조확인 흐름, 결재 화면(결재대기·이력·요청내역) 자체의 단위테스트

| 구분 | 내용 |

| 메뉴 | 메뉴마다 [sychoi] 문서 생성 (메뉴별 방법은 `tests/az303/menus.spec.ts` PREPARE). 결재요청 팝업 제목은 "[sychoi] AZ303 <코드> <시각>" |

## 5. 판정 규칙

**기대값**
- 결재라인 = 운영기준설정 > 승인Flow설정의 그 업무구분(사용 Y) 승인순서
- 요청타입 = 결재유형 이름 (예: 일일업무일지, 구매요청)

**확인된 사양 (오류 아님)**
- 2026-10-26: 버튼 이름은 설계서 "결재요청"이 아니라 화면 "승인요청" — 이름 차이는 오류로 보지 않음 (사용자에게 알림)
- 2026-10-27: 결재자를 바꾼 뒤 저장하지 않고 [승인요청]·[기본 결재자로 저장] 하면 "저장후 사용하세요." (먼저 목록 [저장])
- 2026-10-27 사용자 결정: 제개정은 제정·개정 모두 확인 (제정 TC_035·036·038, 개정 TC_053·054·055). 개정·정기수리계획·점검Group·순회점검은 기존 데이터 사용 허락

- 2026-10-28 사용자 판정: 요청타입 명칭이 다른 것(정기수리계획 "작업결과")은 명칭만 고치면 되므로 **개선**. 요청 후 결재요청 팝업이 안 닫히는 것도 **개선**. 결재요청이 아닌 다른 메뉴 기능 오류(계측기 제정 저장 불가)는 오류로 두되 QA내용 앞에 "[다른 메뉴 오류: …, 별도 요청]" 으로 구분. TC_002·022·EC_001·002 개선, TC_021 정상 그대로

**알려진 오류·개선** (v5, 2026-10-28 사용자 확정)
- 오류(다른 메뉴, 별도 요청) TC_036: 계측기 제정 Revision 팝업 값이 상세로 안 넘어와 계측기번호 필수로 저장 불가
- 개선 TC_002 사원 자동완성 목록이 Lov 를 가림, TC_031 요청타입 명칭 "작업결과"(기대 "작업계획서")
- 2026-10-28 사용자 확정으로 정상: TC_022 요청 후 안내 없음, TC_050·051 요청 후 팝업 안 닫힘, EC_001 제목 길이 초과 안내 없음, EC_002 같은 단계 결재자 중복 저장 (CLAUDE.md 의 "안내 없음 = 개선" 기본값보다 우선)
- 미수행 없음 (2026-10-28 사용자: 미수행은 남기지 않음). TC_006 은 본인 계정으로(로직 동일), TC_018 결재선 변경은 결재요청 팝업 결재자 추가·삭제로, TC_019 결재선(AN110)은 지금 메뉴 "개인설정 > 기본결재자설정"으로 확인
- 2026-10-28 사용자 확인: 점검Group실행은 [확정] 해야 [결재요청]이 보임 (점검값 모두 입력해야 확정됨). 내 담당 건이 없으면 다른 담당자 작업발행 건 한 건 사용 허락(B안)
- 해결됨 (10-28): [mssql] 변경작업항목 탭(사용여부 Y), 순회점검실행 결재요청 버튼(수정 후)
- 해결됨: [mssql] 결재자 목록 저장 안 됨·새 문서 승인요청 팝업 서버오류(errorLogId 78759) — 10-27 빌드 후 정상
