# 결재요청(AZ303) 단위테스트 — 다시 돌리는 법

마지막 정리: 2026-10-28. 프롬프트 `AZ303_prompt.md`, 설계서 `원본/AZ303_FD_결재요청_v1.pptx`.
결재요청은 단독 메뉴가 없는 공통 팝업이라, 팝업 기능은 일일업무일지로 보고(TC_001~025, EC_001~005), 결재 메뉴 27개는 메뉴마다 실제로 승인요청 → 결재대기 승인까지 한다(TC_026~052).

## 1. 돌리기

D:\qa-auto 에서 PowerShell:

```
.\run-az303.ps1                          # oracle: 팝업 기능 → 메뉴 27개
$env:QA_SITE="mssql"; .\run-az303.ps1    # mssql (끝나면 Remove-Item Env:QA_SITE)
.\run-az303.ps1 menus -Only WORKORDER,OHPLAN
.\run-az303.ps1 report                   # 두 사이트 결과 → 엑셀·PDF
```

- 테스트는 `RUN_AZ303=1` 일 때만 돈다. 로그인 파일 `playwright\.auth\user-az303.json` / `user-mssql-az303.json`.
- 같은 계정이라 다른 실행·화면 로그인과 겹치면 세션이 끊긴다. oracle·mssql 도 한쪽에 로그인하면 다른 쪽 세션이 끊김 (2026-10-27 여러 번) → 사이트도 하나씩. 끊기면 그 케이스만 다시.
- 밤새 돌릴 때 끊긴 적 있음(10-26). 끊긴 케이스는 `--last-failed` 로 다시 (`playwright/.data/az303-final/run.sh` 참고).
- QA 서버 빌드 중(404)에는 기다렸다가 다시.
- 한 메뉴에 3~10분. 27개 전체는 2시간 넘게 걸린다.

## 2. 화면 (자동화 메모)

- 결재요청 팝업: 상세 [승인요청](`a.b_approval`, 변경작업 등은 `a.b_apprequest`) → `popupIframe1` 의 `appReqDetail.do` + 결재자 그리드 `tabFrameTAB.appPrcList_appReqDetail`.
- 결재자 칸: 더블클릭하면 사원 자동완성 목록이 뜨지만 글자로 걸러지지 않음 → 칸 안 돋보기 → 사원 Lov(`lovEmpAcList.do`) 에서 사원명으로 고름 (`setApprover`). 자동완성 목록이 Lov 를 가려서 숨김 처리.
- 결재자를 바꾼 뒤에는 목록 [저장]을 먼저 해야 [승인요청]·[기본 결재자로 저장]이 됨 ("저장후 사용하세요.").
- 안내 상자는 확인 버튼 없이 잠깐 떴다 사라짐 → `floatingTexts` / `clickAndCollect` 로 읽음.
- 결재대기: 행 체크박스를 켜고 [결재처리](`b_appraction`) → 팝업 [승인]. 결재 단계마다 한 번씩 나옴 (`approveInInbox`).
- 업무구분(요청타입)은 결재요청을 부른 화면이 정함. 정기수리 작업을 수리작업실행에서 요청하면 "작업결과".
